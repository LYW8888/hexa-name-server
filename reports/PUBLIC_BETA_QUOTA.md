# 公开内测名额与星际东方工作台

本次实施目标：保留免费名字提案，让访客无需邀请码或注册即可按剩余名额主动体验完整报告，阅读后自愿反馈；联系方式仅展示。初始总名额按经营者确认设为100份。完成本地验证与代码交付，未在目标服务器部署。

## 用户与经营者流程

1. 访客在工作区选择预产期、已出生或改名。三条流程保持独立，改名先分析现名再推荐；预产期允许未来日期。
2. 免费生成姓名、读音和寓意，不占报告名额，也不要求手机号登录。顶部显示真实总额、累计已用和剩余。
3. 点击“查看完整报告（内测）”前可看到保存范围：本次出生资料与完整报告加密保存最多30天，成功保存使用1个名额。无需重复输入资料或邀请码，不要求先联系或评分。
4. 可阅读四柱、阴阳五行、生克、旺衰喜用参考、古籍选字依据与改名现名分析，下载完整文字报告。反馈自愿，评分不预填，1–5分均可提交；提案与报告草稿、记录分别处理。
5. 同一份报告在当前页面内可重复打开，不重复计次。凭据只保存在页面内存，刷新/关闭页面后使用已下载文件；报告编号可交给经营者从后台查找。账号存档仍只保存免费提案，不保存报告访问凭据。
6. 经营者登录独立后台→“体验反馈与内测”→“免费体验名额设置”，调整总额或暂停开放；累计已用只读，总额不能低于已用。已有报告在暂停/满额后仍可重复读取。
7. 后台查看、筛选、导出真实意见，标记纳入改进或已处理，按编号查找/导出/删除报告。客服、财务、交付岗位不能访问这些资料或更改名额。

**一个名额=一份成功保存的完整报告，不等于一个独立访客。** 生成请求、刷新名额、收藏、下载、重复查看和反馈不扣次。换组或修改资料后的新一份报告计次。删除、30天到期和重启不会返还或清零已用次数。无需邀请码不等于无限量，公共池可能被同一访客使用多次；本版本没有“一人一份”的身份承诺。

## 并发与异步约束

- 报告服务 SQLite `beta_quota` 单行保存总数/已用；完整报告使用生成编号唯一约束。算法重算与加密在写锁外完成，最终 `BEGIN IMMEDIATE` 中重新校验开放状态，再条件扣减并插入报告，审计同事务提交。
- 同一生成凭据重试先查已存报告；最后一个名额耗尽后也可找回成功保存的报告。失败事务整体回滚，无“已扣次但未保存”中间状态。
- 前端防重复提交；先查本次已存报告，再申请新报告。网络超时、5xx或响应丢失保留“不确定是否保存”的重试入口，先查询原记录，不创建新的生成编号。
- 前端与服务端均校验当前输入及候选一致，不接受浏览器构造的完整报告。切换资料后，晚返回的旧报告不会显示到新提案下。
- 名额响应携带单调递增 `revision`；轮询、手动刷新、窗口恢复与报告回执共用合并逻辑，旧响应不能覆盖新计次。每20秒可见时刷新，窗口恢复刷新；显示的是最新一次已知快照，最终名额以服务端事务为准。
- 配置另有 `config_version`，两个管理员修改产生409提示重新核对；普通用户扣次不造成配置误冲突。后台不能直接修改已用数。
- 名额接口错误显示“待刷新”，保留上次真实值；初次失败显示“—”，不会伪造0或显示固定100。免费名字生成仍可继续。完整报告请求可关闭窗口，后台结果仍绑定原提案。

## 存储、迁移与接口

沿用报告服务私有目录0700、DB0600、原Fernet密钥与Unix socket调用方UID校验。升级自动创建配额表，只初始化一次；将迁移时尚存的历史内测报告记录（包括内容已删除的留存记录）计入已用，初始总额为`max(100,历史条数)`以避免负数。已被旧版彻底清理的历史记录无法追溯。保留原密钥与数据库，不能以新库替换旧库来升级。

| 接口 | 范围 |
| --- | --- |
| `GET /api/beta-quota` | 公开真实计数；服务不可用503，不返回假计数；响应禁止缓存 |
| `POST /api/beta-reports` | 本次生成凭据、明确同意、原输入/候选；按事务使用名额；旧code字段不授予任何额外名额 |
| `POST /api/beta-reports/read` | 本次生成凭据读取已存报告，满额/暂停不影响，不扣次 |
| `POST /api/experience-feedback` | 自愿意见，范围分离、幂等、私有，不提供公开列表 |
| 后台 `POST /api/experience/quota` | 经营者/超级管理员、TOTP会话及CSRF，字段仅总额/状态/配置版本 |
| 旧 `POST /api/report-requests`、创建邀请码 | 410，原流程已退出；历史管理记录保留 |

生成统计不保存姓名、出生资料或原始IP；报告和意见经主动同意才保存，最多30天。访问凭据不进入URL、本机收藏或账号存档；不将合成测试意见称为真实客户反馈。本轮不新增命理算法，也不把匹配值解释为确定性运势。

## 当前界面与设计选择

可选方向：A **星际东方工作台（当前实施）**，深墨导航＋月白内容区，填写与比较并排；B 银白空间玻璃，更轻盈、更偏消费品牌；C 东方编辑式，宣纸与墨色、更偏文化精品。三者是视觉取向，不是框架先进程度排名。沿用React19、Vite8、Radix Themes与Lucide，避免为换框架重写稳定业务逻辑。

当前已改变信息结构：收起巨幅装饰与重复场景入口，一处选择场景；桌面双栏，手机单栏；报告和反馈接在提案下方；账号、心愿卡、方法默认收起；联系方式移到页尾。弹窗与主页面使用同一套明亮阅读样式，保留键盘关闭、焦点管理、减少动态效果、移动端16px输入与44px主要点击区域。

## 更新服务器

需要同时更新**命名服务、独立后台、报告服务**，并重新构建前端。单独刷新浏览器或只重启命名服务不足以启用新模式。

```sh
git pull --ff-only origin main
npm ci --prefix frontend
npm run build --prefix frontend
```

保留原数据库、报告加密密钥和环境文件；按实际systemd服务名称重启三个进程。报告服务启动自动创建配额表，不重置已用。后台身份库无需本轮新增迁移；既有部署仍按服务定义执行原迁移检查。未安装独立报告服务时，先按 [报告服务部署](OPERATOR_REPORTS.md) 配置进程及socket，复用其中部署步骤，忽略该历史文档的人工登记产品流程。

验收：后台可读到实际名额并保存→客户名额显示一致→生成一份合成提案→主动打开完整报告→已用加1→重复打开不加→可自愿反馈→后台可读原始意见。这个验收会实际使用一个名额，不自动返还，可按经营需要提高总额。再检查暂停新报告、恢复开放、公共入口不能读取后台接口及报告数据目录不可公开访问。主机隔离、真实短信、支付与生产重启不属于本地自动化验收。
