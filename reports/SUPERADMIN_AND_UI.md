# 超级管理员与界面更新

本轮根据“随机超级管理员、密码保护、整体页面现代化”实施，不改变免费提案和经营者人工交付完整报告的业务范围。代码已完成本地验证；目标服务器及真实后台域名尚未由本轮部署，不把测试凭据作为线上账号提供。

## 优化后的实施提示词

为序名实现唯一的随机超级管理员及可重复部署的初始化流程：使用安全随机源生成账号和强密码，登录密码采用 Argon2id 单向哈希；首次登录强制改密并保留动态验证码验证。初始凭据仅通过服务器私有文件交付，禁止网站获取、日志输出、重复启动覆盖和网页提权。保留客服、财务、交付与客户数据的现有隔离。使用受维护的现代 React 组件库统一升级客户首页、表单、名字提案、报告联系区和独立管理端，兼顾手机、键盘、加载状态与可读性。完成真实浏览器流程、后台权限和回归测试，补齐首次登录与部署说明后提交代码。

## 账号实现

- `bootstrap_superadmin --write-credentials` 创建 `sa_` 前缀随机账号、43字符随机初始密码和 TOTP 验证器。数据库只保存 Argon2id 密码哈希，旧 PBKDF2 登录后可升级。
- 数据库条件唯一约束确保只有一个超级管理员标记。网页不能设置该标记或停用超级管理员；重复运行初始化不会重置密码、验证器或重新生成初始文件。
- 初始凭据写入 `XUMING_ADMIN_HOME/initial-superadmin.json`：父目录0700、文件0600，拒绝覆盖和符号链接。写入失败回滚数据库与部分文件；非交互模式不能输出明文凭据。
- 首次登录须使用密码和动态码，强制修改并确认新密码；改密后清除初始文件。验证器遗失通过服务器可信终端执行 `reset_operator`，不提供网页密钥查询。
- 超级管理员具有经营者能力，管理员工及客户主动提交的完整报告；财务和客服原始明细仍按岗位隔离。
- 新版 systemd 示例先迁移数据库，再初始化账号。生产部署须安装新 Argon2 依赖并更新服务配置，原账号保留。详见[首次登录步骤](../backoffice/README.md#首次登录)。

## 界面实现

采用 React 19、Radix Themes 3.3.0 与 Lucide 1.66.0；组件和图标版本固定在锁文件。沿用 Vite 8 构建客户与后台两个入口。

- 首页：青玉、雾白配色，东方文字视觉，明确免费、免注册与完整报告入口。
- 表单：三条业务场景保留独立输入和校验；现代卡片、输入组件、生成加载反馈与错误提示。
- 名字提案：姓名与读音优先，收藏、复制、比较按钮采用两列布局；手机点击区域至少44px，避免紧挤和重叠；不显示私有算法报告。
- 联系报告：微信 LCEX511、QQ 19437771；保留客户明确同意、申请编号和后台人工交付链路。
- 管理端：独立登录页、密码可见切换、改密二次确认、岗位侧栏、工作总览和报告工作区。降低辅助文本密度，补强字号与对比度。
- 响应式与访问：手机导航采用有焦点管理的 Dialog；保留键盘焦点、320px窄屏校验、16px手机输入字号与减少动态效果偏好。

共享组件库增加了构建资源体积，本轮未将界面升级表述为加载性能提升。

本地浏览器覆盖随机超级管理员真实登录、首次改密、凭据文件清除、退出及岗位权限，使用临时账户和私有临时凭据文件；无HTTP凭据接口。该测试不等同目标主机不同操作系统账户的隔离验收。

部署顺序：安装 Python 与前端锁定依赖，构建前端，更新并重启独立后台 service（执行迁移与初始化），重启客户页服务，配置后台独立 HTTPS 域名，然后在可信终端读取初始化凭据。沿用已有报告服务与岗位 worker 部署配置。只做 Git 拉取和重启旧版 service 不会自动加入新增的初始化指令，须同步更新 service 或在同一管理账户及受保护环境手动执行。
