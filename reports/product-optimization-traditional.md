# 起名体验与传统计算改进

本轮依据代码检查、本地浏览器操作和自动化回归整理，不代表真实用户访谈或专家认证。

## 产品问题与落实

| 观察到的问题 | 本轮改动 | 验证 |
| --- | --- | --- |
| 名的字数与全名字数容易混淆 | 姓氏联动全名示例、明确“不含姓”，提交前确认字数与数量 | 单姓/复姓、桌面/手机浏览器流程 |
| 最后一步修改前面信息不方便 | 提交前摘要附“修改基本信息 / 修改出生信息”，保留当前输入 | 修改后返回、数量和日期沿用 |
| 生成后先看到长篇排盘，选名字需要反复滚动 | 名字先展示，排盘与来源放在后面；卡片优先短说明 | DOM顺序、手机宽度、页面截图 |
| 收藏只有名字，缺少决策工具 | 当前候选最多3个逐项比较：读音、寓意、字形意象、匹配理由与资料状态；提供比较入口 | 选择/移出/上限/重新生成后清空 |
| 四柱存在，但选名仍靠固定分数和手填卦象 | 移除固定基础分、演示笔画和名字人工卦象；连接年月日时起卦、显式部首规则与偏好排序 | 五行偏好、日期变化、实际出生优先、避用字硬约束 |
| 阴阳五行只有概念说明 | 显示表面八字五行、干支阴阳、藏干、十神和月支本气，区分不同计数口径 | 已知四柱、十神关系、藏干和起卦手算锚点 |
| 下载和账号记录容易与当前页面口径脱节 | 新报告保留计算参数、算式及每项匹配依据；主动保存支持新偏好字段，旧报告仍标旧演示状态 | 客户保存、刷新、下载、删除以及权限隔离回归 |

## 已完成的验证

- Python公共服务：79项测试通过。
- Node前端逻辑：8项测试通过。
- 公共页面：18条Chromium浏览器流程通过，覆盖1280/390px和既有320px检查。
- 客户服务：19项Django测试、4条浏览器流程通过。
- 本地部署自检：React入口、构建资源、接口、未来预产期和3个候选正常。
- 100条合成路径：90条有效路径正常生成，10条预设无效路径均返回校验错误。不是100名真实用户的体验反馈。

## 仍影响正式商业服务的缺口

1. 现有65个候选是有限人工候选集，需继续扩充并审校寓意、读音、经典出处和字表许可。当前未将任何新条目标为人工核验完成。
2. 字形按明确的直接部首规则分组，不能冒充汉字五行的唯一标准。体卦五行是可关闭的文化偏好，不是八字喜用神。格局旺衰、调候、喜用神、大运、真太阳时和康熙笔画数理尚未实现。
3. 起卦声明了常见年月日时口径，并给出参数、六爻和算式；古籍版本、释义和权威历表仍需复核，不能据此承诺运势。
4. 正式收费仍需接通已规划的支付、报告交付与运营制度，并先用少量真实家庭完成可用性访谈。本轮没有开通购买或发布到生产服务器。

算法、数据来源与分项权重见 [规则说明](../data/ALGORITHM.md)。服务器更新需拉取GitHub、安装依赖、构建前端并重启实际服务，然后执行 `scripts/check_site.py`；操作顺序见 [部署说明](../deploy/README.md)。
