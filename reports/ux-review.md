# 客户端与后台体验走查

历史记录：下文的双日期并存方案已由后续明确的场景隔离规则替代，当前行为见[起名与改名流程修正](workflow-correction.md)。

本轮以本地运行的实际页面完成操作，覆盖桌面1280px、手机390px及既有320px检查。输入采用合成资料；不是用户访谈或满意度调查。账号流程使用本地测试短信能力，没有触发真实短信或支付。

## 走查结果与修改

| 场景 | 复现的问题 | 完成的修改 |
| --- | --- | --- |
| 手机连续填写 | 点击下一步后，新步骤标题仍在视窗上方，需要反向找内容 | 切步滚动并聚焦当前标题；已到达步骤可直接返回，保留所有输入 |
| 起名与改名 | 先选对象、再选时间场景的顺序割裂；成人改名还能选择不兼容的预产期流程 | 时间场景移到出生信息步骤；改名自动使用实际出生信息 |
| 双日期 | 两套日期与时间并列，难判断哪些必填、哪套真正采用 | 主时间先展示，另一套可展开保留；实时展示本次采用的时间，实际信息完整时优先采用 |
| 可选日期编辑 | 清空最后一个可选日期时，折叠区会突然关闭 | 折叠由用户操作控制，场景切换时才恢复已有的补充信息 |
| 首次快速体验 | 没有具体偏好也必须完整走到第三步 | 增加“跳过偏好，先生成”；出生信息及其他必填项照常校验 |
| 修改偏好 | “重新生成”沿用旧条件，用户难判断修改是否生效 | 区分“应用修改并生成”与“换一组名字”；待应用修改有明确提示，提供直接调整入口 |
| 请求失败 | 新请求失败会清掉已经生成的名字 | 保留上一份方案，仍可查看、收藏和下载；原填写继续保留以便重试 |
| 浏览不同候选 | 换组后找不回上一组，比较清单被清空 | 内存保留本次浏览历史，上一组/下一组可恢复；缓存组直接显示，跨组比较最多3个 |
| 候选看完 | 持续轮换到重复的组，容易感觉按钮没有效果 | 已看完当前条件的候选后停止换组，提示调整条件；重复出现的名字标记“此前看过” |
| 收藏入口 | 收藏列表在长页面中，查找、复制和返回原方案不连贯 | 增加独立收藏面板，支持名字/无声调拼音/寓意搜索、复制清单、心愿卡，以及回到本次浏览过的方案 |
| 清空收藏 | 一次点击就丢掉本机清单 | 提供10秒撤销；面板支持键盘关闭并回到触发按钮，打开时不自动弹出搜索键盘 |
| 无匹配候选 | 只有文字说明，用户要自己找到需要改的字段 | 提供“修改避用字”“调整名的字数”，直接定位相应步骤与字段 |
| 账号暂不可用 | 用户进入“我的服务”后又被送回起名表单 | 已生成方案时可直接下载，也能打开本机收藏 |
| 账号重复保存 | 来回翻组后再次保存同一组，可能重复占用保存数量 | 同一组复用保存编号；删除后生成新编号，允许重新保存 |

390×844的一次实际操作样本：原第二、三步标题分别落在视窗上方约689px、456px；修改后均定位到视窗顶部约24px。该数据只描述这一尺寸与路径，不代表所有设备的量化提升。

## 后台体验范围

完成经营者登录、汇总与员工开通，客服工单登记及状态流转，财务手工登记及冲销，交付授权到完成及重复请求复用等主要路径。包含手机尺寸检查和岗位接口隔离检查。

## 数据行为

表单和浏览历史只保留在本次页面内存。收藏仍只写入名字、拼音、寓意及资料类别，复制收藏清单不带出生信息；账号保存仍需主动确认。候选比较限同一次条件下的不同组，应用新条件时重建比较范围，避免跨条件误比匹配值。

## 验证

- Python公共服务：105项。
- Node前端逻辑：14项。
- 公共页面浏览器流程：30项，含新增的步骤定位、双日期、快速生成、跨组比较、失败保留、收藏回路与候选结束状态。
- 客户服务：19项Django测试、5项浏览器流程。
- 后台：4项浏览器流程，覆盖经营、客服、财务与交付。

合计177个独立用例通过；修复后的定向重跑不重复计数。前端构建及本地站点入口、静态资源、未来预产期生成检查通过。浏览器检查使用Chromium；真实短信供应商、实际支付与线上部署不属于本轮本地验收。
