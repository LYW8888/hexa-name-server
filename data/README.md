# 命名算法数据库

这里保存可审计、可替换的命名数据。每条资料都需要携带来源和核验状态，未核验内容不能在产品中显示为确定的经典出处。

## 数据分层

- `character-catalog.json`：汉字基础资料、五行候选归类、读音、风格和字义。
- `names.json`：候选名、拼音、寓意、偏好标签和资料状态的唯一数据源；接口负责筛选、排序并返回完整展示依据。现有条目为待核验或演示资料，缺少可复核出处时不标为已核验。
- `phonetics.py`：通过固定版本的第三方字典辅助对照姓名逐字读音；其结果不取代姓氏读音、词典出处或方言谐音的人工核验。
- `classics.json`：八卦象意、阴阳和五行规则的来源索引与核验状态。
- 四柱由 `bazi.py` 根据输入实时计算，不存储在本目录；后续仍需补充权威历表复核案例、康熙笔画、卦象资料、禁用字与谐音词表。

## `verification_status`

- `demo`：仅用于当前原型演示。
- `pending`：已录入但需要人工或权威资料复核。
- `verified`：完成实际人工复核，并在 `meaning_source.reference` 中记录来源标题、版本、具体位置、链接、使用许可、复核人和日期；这些字段缺失时服务会拒绝加载字库。字段完整只能保证可追溯，不能代替人工核验。

当前仓库只包含演示和待核验数据，不宣称提供完整命理数据库。

算法输入还需要记录场景（due_date/born）、时间精度和性别偏好，避免把预产期参考时间误当作实际出生时间。
