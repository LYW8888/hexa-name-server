# 上传资料与古籍取名数据

- `raw/`：用户提供的10份原始资料，按原始字节保存；不从HTTP公开。
- `sources.json`：来源、上传文件SHA-256、是否进入自动取名；文件头的上游项目和许可声明保留在原文中，不把上传说明当作独立底本认证。
- `phrases.json`：82个编辑选取的命名片段。每条保留原句、篇章、原文件行号与现代释义；导入时逐条与原文核对，找不到就失败。
- `positive-characters.json`：121个编辑选择的正向义项；`context_only`表示该义项仅用于原片段，不能默认拆出任意组合。
- `rules.json`：可复算的六维权重、部首分组、民俗数理、声调表、词条黑名单和搜索预算。阈值及配分是项目选择。
- `surname-readings.json`：常见多音姓参考读法，用户可指定自己的姓氏读音；不是对所有家族实际读法的断定。

导入命令：`python3 scripts/import_naming_corpus.py`。生成的SQLite含来源、篇章正文、字典记录、取名片段、正向义项和版本指纹，未保存任何客户出生信息。构建完成后以只读方式供隔离的客户服务使用。

校正记录：不采用“欧8阳6”“魏17”的现代笔画混用；不猜清等缺录字的康熙笔画。五行、八字概括资料和八卦重复录文保留参考，不作为名字的独立双典。周易上传录文的“大明始终”“恐惧修身”等异文不擅改，也不作为本次取名引用；路漫漫、车舝等按实际上传文字定位。

`text_matched`指已与本次上传文件匹配，显示为“原句已对照”；与完整版本校勘和名字原词的判定分别记录。现代释义为项目编写，跨篇组合会明确标注。

尚无可验证的近五年出生用字频率与姓名总体数据，热度与重名概率校正未启用。候选组合使用编辑顺序而不是伪造的频率榜。
