# 经营、客服与财务：隔离基础

这是部署在服务器内部的命令行基础工具，不是已上线的管理后台。它提供两套彼此独立的最小登记：

- 客服：创建工单编号、类别和状态，查看列表与状态汇总。没有姓名、手机号、出生资料、对话内容或订单关联字段，**不能代替正式客服系统**。
- 财务：手工登记人民币收入、支出、退款金额（单位为分），并以反向记录撤销错误登记。汇总是登记金额的算术合计，**不是银行余额、会计报表或支付对账**。没有支付、转账、退款或修改订单的能力。
- 经营者：通过各岗位提供的汇总掌握工单状态及登记金额；当前没有管理者登录、总览界面或自动报表。需要使用真实的身份、审批和独立审计系统，不能用共享账号代替。

两个登记使用不同数据库和操作系统账户，不接入公网站点或前端。必须先按下列条件配置并在目标机器验证，才有操作系统层面的隔离。当前仓库没有为目标服务器配置这些条件。

## 职责边界与流程

| 角色 | 当前登记能力 | 不应默认授予的能力 |
| --- | --- | --- |
| 经营者 | 接收客服状态汇总、财务登记汇总；审批岗位与高风险操作 | 直接访问出生资料、客服对话和原始支付资料 |
| 客服 | 分类、流转工单；仅记录非敏感状态 | 查看财务账目、操作退款或访问支付密钥 |
| 财务 | 手工记账、对原记录做一次冲销；查看汇总 | 查看客服内容、单人完成退款审批与付款 |
| 系统管理员 | 维护主机、账号及备份 | 默认参与业务审批；管理员具备主机高权限，技术上可以绕过本机隔离 |

客服状态为 `open` → `in_progress` → `resolved` → `closed`；处理中也可关闭，已解决可退回处理中或关闭。关闭后不能重开，后续问题新建工单。系统不记录实际服务内容，不要把客户信息放进命令、环境变量、终端输出、工单编号或日志。

真正的退款流程尚未实现。上线支付前应通过经过审查的支付和订单系统建立“客服受理 → 财务核对 → 独立审批 → 原渠道退款 → 对账”流程，设置权限、金额阈值和异常复核；不要把本工具中的 `refund` 登记当作已退款。财务错误使用 `reverse` 留存冲销记录；本工具没有与订单或真实凭证关联，实际账务仍须由财务人员独立核对。

## 主机隔离的部署前提

1. 客户网站 `xuming`、客服 `xuming-support` 和财务 `xuming-finance` 必须是不同的系统用户，数据库目录分别由各自账号拥有，不共享可写组。应用代码与 Python 运行环境应由管理员维护，业务账号只读；公网进程和反向代理不能读取操作目录。
2. 由管理员在目标机器上创建这两个无交互登录的系统账号，并创建 `/var/lib/xuming-ops/support` 和 `/var/lib/xuming-ops/finance`。父目录由管理员控制且不可被业务账号写入，两个子目录分别由对应账号独占，权限 `0700`；工具以 `0600` 创建数据库。代码会拒绝 root、错误角色、宽松权限、符号链接和非本账号所有的目录或数据库；这些检查不能取代系统权限配置，也不能防范拥有主机 root 权限的人。
3. 为员工使用各角色账号配置个人身份认证、多因素认证和最小授权，记录个人账号到角色的使用事件；不要让多人直接共享凭据。角色账号身份只能表明岗位，工具本身**不能识别具体员工**。账号离职即时撤权，定期复核权限。避免赋予可任意执行命令或切换账号的宽泛 sudo 权限；应使用受控的身份代理及操作接口后再开放给员工。
4. 本工具的审计记录写入各自数据库，记录动作与时间，不含真实员工身份。它有防止普通 SQL 更新和删除的触发器，但数据库所有者或主机管理员可以绕过，**不是防篡改审计**。上线需把认证、授权、访问和变更事件送往独立受控的集中审计，并验证告警和保留策略；失败或越权尝试依赖系统审计。
5. 分别加密备份和存放密钥，限制备份及恢复权限，定期演练恢复；不能让公网服务或客服读取财务备份，或让财务读取客服备份。按实际业务和适用要求制定保留及删除周期，当前无自动清理或备份功能。
6. 先用测试数据验证两账号相互拒绝、网站进程无法读取、`/operations/console.py` 及数据库无法通过 HTTP 获取；复核系统账户、文件权限、备份、日志和代理配置。当前自动化测试模拟身份并检查权限，不能替代目标主机上的跨账号验证。

## 使用示例（管理员预先完成配置后）

以下仅演示在受控终端使用测试数据；实际命令须由经过批准的身份代理执行，`/opt/xuming/app` 应为只读代码目录。示例中的 `sudo` 是管理员验证方式，**不是**面向员工的授权配置。

```sh
sudo -u xuming-support python3 /opt/xuming/app/operations/console.py support init
sudo -u xuming-support python3 /opt/xuming/app/operations/console.py support create --category technical
sudo -u xuming-support python3 /opt/xuming/app/operations/console.py support move --id '工单UUID' --status in_progress
sudo -u xuming-support python3 /opt/xuming/app/operations/console.py support summary

sudo -u xuming-finance python3 /opt/xuming/app/operations/console.py finance init
sudo -u xuming-finance python3 /opt/xuming/app/operations/console.py finance record --kind income --amount-fen 9900
sudo -u xuming-finance python3 /opt/xuming/app/operations/console.py finance reverse --id '原登记UUID'
sudo -u xuming-finance python3 /opt/xuming/app/operations/console.py finance summary
```

将示例中的 UUID 替换成创建时返回的实际编号。两岗位都支持 `list` 和 `audit`；只返回最近 200 条。分类为 `usage`、`naming`、`technical`、`other`；财务类型为 `income`、`expense`、`refund`。一笔冲销只能执行一次，冲销记录不能再次冲销；如需修正，应新增正确的登记。此工具不收集自由文本，不应添加客户信息作为参数。

此工具不提供网页端身份认证、权限管理、客户资料、收款、发票、真实对账、自动报表、审批、加密或集中审计。需要这些能力时，应分别设计、测试和审查后再接入真实业务。
